## Introducción

La **estructura del contenido** es tan importante como el contenido mismo. Un artículo con información valiosa pero mal estructurado:
- **No rankea bien** (Google valora contenido escaneable y bien organizado)
- **No retiene usuarios** (bounce rate alto)
- **No convierte** (usuarios se pierden sin llegar al CTA)

Este documento define la estructura estándar para todo contenido de Livo, optimizada para:
- **SEO**: Google puede crawlear y entender fácilmente
- **UX**: Usuarios encuentran información rápidamente
- **AI-Search**: IA puede extraer y citar información
- **Conversión**: Guía al usuario hacia acción deseada

### Principios Fundamentales

1. **Escaneable**: 80% de usuarios escanean vs leen palabra por palabra
2. **Jerárquico**: Información más importante primero (pirámide invertida)
3. **Fragmentado**: Secciones cortas con headers claros
4. **Visual**: Elementos visuales cada 300-400 palabras
5. **Accionable**: CTAs claros y relevantes

### Longitud Óptima por Tipo

| Tipo de contenido | Longitud recomendada | Razón |
|-------------------|---------------------|-------|
| **Landing page transaccional** | 800-1500 palabras | Suficiente para informar + convertir sin abrumar |
| **Blog post informacional** | 1500-2500 palabras | Profundidad para rankear + autoridad |
| **Pillar content / Guía completa** | 3000-5000 palabras | Cobertura exhaustiva del tema |
| **Listicle** | 1200-2000 palabras | Depende del número de ítems |
| **How-to guide** | 1500-2500 palabras | Detalle suficiente para ser accionable |
| **Comparativa** | 1800-2500 palabras | Análisis balanceado con datos |
| **Caso de uso** | 1000-1500 palabras | Historia + resultados + learnings |

**Regla de oro**: **Tan largo como sea necesario, tan corto como sea posible**.
- No añadir "fluff" para alcanzar word count
- Cubrir el tema exhaustivamente sin redundancia

## Estructura de Headlines (H1-H6)

### H1: El Título Principal

**Reglas**:
- ✅ **UNO por página** (crítico para SEO)
- ✅ **Incluir keyword principal** (idealmente al inicio)
- ✅ **40-60 caracteres** (legible sin truncar)
- ✅ **Claro y directo** (usuario sabe de qué trata)
- ✅ **Atractivo** (motiva a leer)

**Fórmulas que funcionan**:

1. **[Número] + [Adjetivo] + [Keyword] + [Beneficio]**
   - "10 Estrategias Efectivas para Contratar Enfermeras Rápidamente"
   - "7 Formas Probadas de Reducir Absentismo en Hospitales"

2. **Cómo + [Acción] + [Keyword] + [Timeframe/Resultado]**
   - "Cómo Contratar Enfermeras en Barcelona en Menos de 5 Horas"
   - "Cómo Reducir Costes de Personal Eventual Hasta un 30%"

3. **[Keyword] + Guía Completa + [Año]**
   - "Pool de Enfermeras: Guía Completa 2026"
   - "Contratación de Personal Sanitario: Guía para Hospitales 2026"

4. **[Keyword] vs [Alternativa]**
   - "Pool de Enfermeras vs ETT: Comparativa Completa"
   - "Livo Pool vs Hublo: ¿Cuál Elegir en 2026?"

5. **Todo lo que Necesitas Saber sobre [Keyword]**
   - "Todo lo que Necesitas Saber sobre Pools de Enfermeras"

**Ejemplos para Livo**:

**❌ Mal**:
- "Enfermeras" (demasiado vago)
- "La mejor plataforma para contratar enfermeras eventuales en hospitales privados de Barcelona y alrededores" (demasiado largo)
- "¡Contrata enfermeras YA!" (clickbait, poco profesional)

**✅ Bien**:
- "Contratar Enfermeras en Barcelona: Guía Completa 2026"
- "Pool de Enfermeras vs ETT: Comparativa para Hospitales"
- "Cómo Reducir Absentismo de Enfermería en 30 Días"

### SEO Title vs H1

**Pueden (y a veces deben) ser diferentes**:

**SEO Title**: Optimizado para SERPs (search engine results pages)
- Aparece en Google
- Puede incluir brand ("| Livo")
- Puede ser más largo (hasta 60 chars)
- Foco: CTR + Keywords

**H1**: Optimizado para usuarios en página
- Aparece en el artículo
- No necesita brand (ya están en tu sitio)
- Puede ser más creativo
- Foco: Engagement

**Ejemplo**:

```html
<title>Contratar Enfermeras Barcelona: Guía 2026 | Livo</title>

<h1>Cómo Contratar Enfermeras en Barcelona en Menos de 5 Horas</h1>
```

### H2: Secciones Principales

**Reglas**:
- ✅ **3-7 H2s** por artículo (estructura clara sin fragmentar demasiado)
- ✅ **Incluir keywords secundarias** cuando sea natural
- ✅ **Descriptivos** (usuario sabe qué esperar en sección)
- ✅ **Orden lógico** (flujo narrativo coherente)

**Estructura típica**:

**Para How-To Guide**:
```
H1: Cómo [Acción]
  H2: ¿Qué es [Concepto]? (contexto)
  H2: ¿Por qué [Acción] es importante? (motivación)
  H2: Paso 1: [Primer paso]
  H2: Paso 2: [Segundo paso]
  H2: Paso 3: [Tercer paso]
  H2: Errores Comunes a Evitar
  H2: Conclusión
  H2: FAQ
```

**Para Comparativa**:
```
H1: [A] vs [B]: Comparativa
  H2: ¿Qué es [A]?
  H2: ¿Qué es [B]?
  H2: Diferencias Clave
  H2: Ventajas de [A]
  H2: Ventajas de [B]
  H2: ¿Cuál Elegir?
  H2: Conclusión
  H2: FAQ
```

**Para Listicle**:
```
H1: [Número] [Cosas]
  H2: Introducción
  H2: 1. [Primera cosa]
  H2: 2. [Segunda cosa]
  H2: 3. [Tercera cosa]
  ...
  H2: Conclusión
  H2: FAQ
```

**Ejemplos para Livo**:

```
H1: Pool de Enfermeras: Guía Completa 2026

  H2: ¿Qué es un Pool de Enfermeras?
  H2: Cómo Funciona un Pool de Enfermeras
  H2: Pool de Enfermeras vs ETT: Diferencias Clave
  H2: Ventajas de Implementar un Pool de Enfermeras
  H2: Cómo Elegir la Plataforma de Pool Adecuada
  H2: Casos de Uso: Hospitales que Usan Pools
  H2: Conclusión: ¿Es un Pool Adecuado para Tu Hospital?
  H2: Preguntas Frecuentes sobre Pools de Enfermeras
```

### H3: Subsecciones

**Reglas**:
- ✅ **0-4 H3s por cada H2** (fragmentar contenido complejo)
- ✅ **Mantener jerarquía** (H3 siempre dentro de H2)
- ✅ **Específicos** (más detallados que H2)

**Ejemplo**:

```
H2: Ventajas de Implementar un Pool de Enfermeras

  H3: 1. Reducción de Costes
  [Contenido sobre ahorro en comisiones, etc.]

  H3: 2. Velocidad de Cobertura
  [Contenido sobre tiempos de respuesta]

  H3: 3. Flexibilidad Operativa
  [Contenido sobre adaptarse a demanda variable]

  H3: 4. Calidad del Personal
  [Contenido sobre verificación, ratings]
```

### H4-H6: Uso Esporádico

**En general, H1-H3 son suficientes** para la mayoría de contenido.

**H4-H6**: Solo para contenido muy técnico o guías extremadamente largas (5000+ palabras).

**Regla**: Si necesitas H5-H6, probablemente deberías dividir en artículos separados.

## Introducción y Hook

### Anatomía de una Introducción Efectiva

**Estructura** (100-150 palabras):

```
[Hook - 1 oración]
↓
[Problema/Pain point - 2-3 oraciones]
↓
[Promesa del artículo - 1-2 oraciones]
↓
[Preview de contenido - 1 oración]
```

### 1. Hook: Primera Oración

**Objetivo**: Captar atención inmediatamente.

**Técnicas**:

**A) Estadística impactante**:
```
El 73% de los hospitales privados en España luchan para cubrir turnos
de enfermería en menos de 48 horas.
```

**B) Pregunta directa**:
```
¿Cuántas veces has tenido que llamar a 3 o 4 ETTs diferentes para cubrir
un solo turno de enfermería?
```

**C) Declaración bold**:
```
Las ETTs tradicionales están obsoletas, y los hospitales que no lo entiendan
pagarán un 30% más en costes de personal durante 2026.
```

**D) Escenario relatable**:
```
Es viernes a las 4pm y acabas de recibir la llamada: dos enfermeras han
llamado diciendo que están enfermas y no pueden cubrir sus turnos del fin
de semana.
```

**E) Hecho contraintuitivo**:
```
Contratar enfermeras eventuales NO tiene que ser caro ni lento, a pesar
de lo que las ETTs quieren hacerte creer.
```

### 2. Problema/Pain Point

**Objetivo**: Conectar con la situación del lector.

**Ejemplo para B2B (Hospitales)**:
```
La mayoría de hospitales dependen de ETTs tradicionales para cubrir bajas
y vacaciones, lo que resulta en:
• Costes elevados (comisiones del 20-40%)
• Tiempos de espera largos (48-72 horas promedio)
• Falta de control sobre quién cubre el turno
• Procesos administrativos complicados
```

**Ejemplo para B2C (Enfermeras)**:
```
Como enfermera, probablemente te has enfrentado a:
• Agencias que te prometen turnos pero nunca te llaman
• Tarifas bajas con comisiones altas que se quedan las agencias
• Falta de flexibilidad para elegir cuándo y dónde trabajar
• Pagos que tardan semanas en llegar
```

### 3. Promesa del Artículo

**Objetivo**: Decir explícitamente qué obtendrá el lector.

**Estructura**: "En este artículo/guía, descubrirás..."

**Ejemplo**:
```
En esta guía completa, descubrirás:
✓ Qué es un pool de enfermeras y cómo funciona exactamente
✓ Las diferencias clave entre pools y ETTs tradicionales
✓ Cómo los hospitales están reduciendo costes hasta un 30% con pools
✓ Los 5 factores para elegir la plataforma de pool adecuada
✓ Casos de éxito reales de hospitales que han implementado pools
```

### 4. Preview de Contenido

**Opcional**: Para artículos largos, mencionar el flujo.

**Ejemplo**:
```
Empezaremos con los conceptos básicos, luego exploraremos las ventajas,
y finalmente te guiaremos paso a paso para implementar un pool en tu hospital.
```

## Cuerpo del Contenido

### Estructura de Párrafos

**Reglas de oro**:

1. **Párrafos cortos**: 2-4 oraciones (3-5 líneas en pantalla)
2. **Una idea por párrafo**: Fácil de escanear
3. **Variación de longitud**: Mix de párrafos cortos (1-2 líneas) y medianos (3-5 líneas)
4. **Espaciado**: Línea en blanco entre párrafos

**❌ Mal** (Wall of text):
```
Los pools de enfermeras son plataformas digitales que conectan hospitales
con enfermeras eventuales de forma directa eliminando intermediarios
tradicionales como las ETTs. Funcionan mediante una app o web donde los
hospitales publican turnos disponibles especificando fecha horario
especialidad requerida y tarifa ofrecida y las enfermeras registradas en
la plataforma reciben notificaciones de turnos cercanos a su ubicación
y pueden aceptarlos directamente. El hospital ve el perfil de la enfermera
incluyendo verificación de titulación experiencia y ratings de otros
hospitales antes de confirmar. Una vez confirmado el turno ambas partes
reciben todos los detalles y la enfermera acude al hospital el día indicado.
```

**✅ Bien** (Párrafos fragmentados):
```
Los pools de enfermeras son plataformas digitales que conectan hospitales
con enfermeras eventuales de forma directa, eliminando intermediarios
tradicionales como las ETTs.

**¿Cómo funcionan?**

Los hospitales publican turnos disponibles en la plataforma, especificando:
• Fecha y horario
• Especialidad requerida (DUE, TCAE, matrona...)
• Tarifa ofrecida

Las enfermeras registradas reciben notificaciones de turnos cercanos a su
ubicación y pueden aceptarlos directamente con un clic.

Antes de confirmar, el hospital puede ver el perfil completo de la enfermera,
incluyendo verificación de titulación, experiencia previa, y ratings de
otros hospitales.

Una vez confirmado, ambas partes reciben todos los detalles del turno y la
enfermera acude al hospital el día indicado.
```

### Uso de Listas

**Cuándo usar listas**:
- Enumerar características, beneficios, pasos
- Comparar opciones
- Presentar datos de forma escaneable

**Tipos**:

**1. Listas con bullets (•)**:
Para ítems sin orden específico.

```markdown
Ventajas de los pools de enfermeras:
• Reducción de costes (comisiones 15-20% vs 20-40%)
• Cobertura rápida (4-5 horas vs 48-72 horas)
• Mayor control y visibilidad
• Proceso 100% digital
```

**2. Listas numeradas**:
Para pasos, rankings, o cuando el orden importa.

```markdown
Cómo cubrir un turno con Livo en 5 pasos:
1. Publica el turno en la plataforma (2 minutos)
2. Recibe notificaciones de enfermeras interesadas (1-2 horas)
3. Revisa perfiles y selecciona candidata (10 minutos)
4. Confirma el turno (1 clic)
5. La enfermera acude el día indicado
```

**3. Listas con checkmarks (✓)**:
Para resaltar beneficios o features.

```markdown
Con Livo Pool obtienes:
✓ Acceso a 50,000+ enfermeras verificadas
✓ Cobertura promedio en <5 horas
✓ Comisión 15-20% (vs 20-40% de ETTs)
✓ Sin costes de setup ni mensualidades
✓ Ratings y reviews de cada profesional
```

**Límite**: 3-7 ítems por lista (ni muy corta ni abrumadora).

Si tienes >10 ítems, considera dividir en sublistas o tabla.

### Tablas Comparativas

**Cuándo usar**:
- Comparar opciones (productos, servicios, métodos)
- Presentar datos estructurados
- Especificaciones técnicas

**Estructura**:
```markdown
| Característica | Pool Digital | ETT Tradicional |
|----------------|--------------|-----------------|
| Comisión | 15-20% | 20-40% |
| Tiempo de cobertura | 4-5 horas | 48-72 horas |
| Verificación profesional | Sí (titulación + ratings) | Sí (titulación) |
| Gestión administrativa | Digital (automática) | Manual |
| Transparencia tarifas | Total | Limitada |
| Costes setup | €0 | €0-500 |
| Costes mensuales | €0 | €0-200 |
```

**Tips**:
- **Header row en bold**: Primera fila con nombres de columnas
- **Primera columna**: Categorías/características
- **Responsive**: No más de 4-5 columnas (legibilidad mobile)
- **Highlight diferencias clave**: Negrita o emojis (✓ ✗)

### Uso de Bold, Italic, Quotes

**Bold (negrita)**:
- **Keywords importantes** (con moderación, no todo)
- **Datos clave** o números relevantes
- **Términos técnicos** la primera vez que aparecen
- **Highlights** en listas

**Ejemplo**:
```
Livo Pool tiene una tasa de cobertura del **85%** en menos de 24 horas,
significativamente superior al **45-50%** de las ETTs tradicionales.
```

**Italic (cursiva)**:
- *Énfasis suave* (vs bold que es énfasis fuerte)
- Términos extranjeros
- Títulos de publicaciones

**Uso limitado** (puede dificultar lectura si se abusa).

**Quotes (blockquotes)**:
- Testimonios
- Citas de estudios/fuentes
- Destacar insights importantes

**Ejemplo**:
```markdown
> "Antes de Livo, cubrir turnos de fin de semana era una pesadilla de 3 días.
> Ahora, publico el turno el lunes y el viernes ya está cubierto. La diferencia
> ha sido radical."
>
> — Dra. Carmen López, Directora de Enfermería, Hospital Quirónsalud Barcelona
```

### Cajas de Destacado

**Uso**: Llamar atención a información crítica.

**Tipos**:

**1. Pro Tip / Consejo**:
```markdown
💡 **Pro Tip**: Para turnos de último momento (urgencias en <24h), activa
notificaciones push en la app de Livo. Las enfermeras cercanas recibirán
alerta inmediata y la tasa de cobertura para urgencias es del 70%.
```

**2. Warning / Advertencia**:
```markdown
⚠️ **Importante**: Si contratas a la misma enfermera eventual más de 6 meses
en un período de 18 meses para el mismo puesto, el contrato puede convertirse
automáticamente en indefinido según el RD-Ley 32/2021. Para evitarlo, rota
profesionales o usa diferentes turnos.
```

**3. Resumen / TL;DR**:
```markdown
📊 **Resumen**: Pool de enfermeras vs ETT
• **Costes**: Pool 15-20% comisión | ETT 20-40%
• **Velocidad**: Pool 4-5h | ETT 48-72h
• **Mejor para**: Pool = hospitales con necesidad frecuente | ETT = necesidad esporádica
```

**Límite**: 1-2 cajas por sección H2 (si hay demasiadas, pierden impacto).

## Conclusión y CTAs

### Estructura de Conclusión

**Objetivo**: Resumir + motivar acción.

**Componentes** (100-200 palabras):

```
[Resumen de puntos clave - 3-5 bullet points]
↓
[Refuerzo del beneficio principal - 1-2 oraciones]
↓
[CTA claro y específico]
↓
[Próximos pasos (opcional)]
```

### Tipos de CTAs según Contenido

**1. Bottom of Funnel (Landing pages transaccionales)**:
- CTA directo y fuerte
- Ejemplos:
  * "Solicita una Demo"
  * "Empieza Gratis Hoy"
  * "Habla con Nuestro Equipo"

**2. Middle of Funnel (Blog posts, comparativas)**:
- CTA más suave, educativo
- Ejemplos:
  * "Descarga la Guía Completa [PDF]"
  * "Calcula Tu Ahorro con Nuestra Calculadora"
  * "Lee Casos de Éxito de Hospitales Similares"

**3. Top of Funnel (Contenido muy informacional)**:
- CTA de nurturing
- Ejemplos:
  * "Suscríbete a Nuestro Newsletter"
  * "Lee Más Artículos sobre [Tema]"
  * "Descarga Nuestro Whitepaper Gratuito"

### Posicionamiento de CTAs

**Regla**: Al menos **2 CTAs** por artículo.

**Posiciones**:

1. **Inline CTAs** (dentro del contenido):

## Content Formatting

### Legibilidad

**Font Size**:
- Body text: 16-18px (mínimo)
- Headings: Escala proporcional (H1: 32-36px, H2: 24-28px, H3: 20-22px)

**Line Height**:
- 1.5-1.7 para body text
- Mayor line height = más fácil de leer

**Ancho de Línea**:
- 50-75 caracteres por línea (óptimo para legibilidad)
- ~600-800px de ancho de columna

**Contraste**:
- Text: Dark gray (#333) en fondo blanco (mejor que negro puro)
- Evitar gray claro sobre blanco (bajo contraste)

### Uso de Color

**Destacados**:
- **Primary color** (brand): Para CTAs, links importantes
- **Secondary color**: Para highlights, datos clave
- **Neutral colors**: Para body text, backgrounds

**Ejemplo para Livo**:
- Primary (azul Livo): CTAs, links
- Secondary (verde): Datos positivos, checkmarks
- Rojo suave: Advertencias, datos negativos
- Gray scale: Texto, backgrounds

### Espaciado

**Entre elementos**:
- Entre párrafos: 16-24px
- Entre secciones (H2): 40-60px
- Entre H2 y contenido: 16-24px
- Entre H3 y contenido: 12-16px

**Márgenes**:
- Imágenes: 24-32px arriba y abajo
- Tablas: 24px arriba y abajo
- Quotes: 24px arriba y abajo + indentación izquierda

**Whitespace es tu amigo**: No tener miedo al espacio en blanco. Hace contenido más respirab le.

## Elementos Visuales

### Tipos de Visuales

**1. Imágenes Hero**:
- **Dónde**: Top del artículo (después de H1 o intro)
- **Tamaño**: 1200x630px (óptimo para shares en redes)
- **Tipo**: Relevante al tema, profesional
- **Alt text**: Descriptivo incluyendo keyword

**Ejemplo**:
```html
<img src="/images/pool-enfermeras-hospital.jpg"
     alt="Enfermera usando app de Livo Pool para aceptar turno en hospital"
     width="1200"
     height="630">
```

**2. Imágenes In-Content**:
- **Frecuencia**: Cada 300-400 palabras
- **Tipo**:
  * Screenshots (para guías how-to)
  * Fotos relevantes (profesionales, no stock genérico)
  * Gráficos/ilustraciones propias
- **Positioning**: Centradas o alineadas según diseño
- **Caption**: Breve descripción si aporta contexto

**3. Infografías**:
- **Cuándo**: Datos complejos, procesos, comparativas
- **Beneficio**: Altamente shareable, aumenta engagement
- **Tamaño**: Vertical (800x2000px+) o horizontal (1200x800px)

**Ejemplos para Livo**:
- "Cómo Funciona Livo Pool en 5 Pasos [Infografía]"
- "Pool vs ETT: Comparativa Visual"
- "Anatomía de un Turno Cubierto en <5 Horas"

**4. Gráficos y Charts**:
- **Cuándo**: Presentar datos, tendencias, estadísticas
- **Tipos**:
  * Bar charts (comparaciones)
  * Line charts (tendencias temporales)
  * Pie charts (distribuciones - usar con moderación)

**Herramientas**:
- Canva (fácil, templates)
- Chart.js (gráficos interactivos web)
- Google Charts (embeddable)

**5. Videos**:
- **Cuándo**: Demos, tutoriales, testimonios
- **Duración**: 2-5 minutos (máximo 10 min)
- **Hosting**: YouTube (embeddable) + transcripción en página
- **Posición**: Inline relevante a sección o al final

**Ejemplo**:
```markdown
## Cómo Publicar un Turno en Livo Pool

[Texto explicativo...]

**Video tutorial** (3 min):

[Embed YouTube]

**Transcript para quienes prefieren leer**:
[Transcripción completa del video]
```

### Optimización de Imágenes (SEO)

**Checklist**:
- [ ] **Alt text descriptivo** (no "imagen1.jpg")
- [ ] **Filename descriptivo** (ej: pool-enfermeras-hospital-barcelona.jpg)
- [ ] **Tamaño optimizado** (<150 KB para in-content, <200 KB para hero)
- [ ] **Formato moderno** (WebP con fallback JPG)
- [ ] **Dimensiones apropiadas** (no cargar 3000px para mostrar 800px)
- [ ] **Lazy loading** (excepto hero image)

**Ejemplo de alt text**:

**❌ Mal**:
```html
<img src="image1.jpg" alt="imagen">
```

**✅ Bien**:
```html
<img src="enfermera-livo-pool-app.jpg"
     alt="Enfermera revisando turnos disponibles en la app de Livo Pool">
```

## Internal Linking

### Estrategia de Internal Links

**Objetivos**:
1. **SEO**: Distribuir PageRank, ayudar a crawling
2. **UX**: Guiar usuario a contenido relacionado
3. **Conversión**: Llevar a landing pages/CTAs

**Número de links**:
- **Mínimo**: 3-5 internal links por artículo
- **Máximo**: No hay límite duro, pero ~10-15 para artículos largos

**Tipos**:

**1. Contextual Links** (inline):
- Dentro del texto, natural
- Anchor text descriptivo (keywords)

**Ejemplo**:
```markdown
Los pools de enfermeras funcionan de forma similar a aplicaciones como Uber,
pero para el sector sanitario. Si quieres profundizar en cómo exactamente
funciona el proceso, lee nuestra [guía paso a paso de Livo Pool](/livo-pool/como-funciona/).
```

**2. Related Content Links** (al final):
- Sección dedicada con 3-5 artículos relacionados
- Títulos descriptivos + breve descripción

**Ejemplo**:
```markdown
## Artículos Relacionados

**[Pool de Enfermeras vs ETT: Comparativa Completa](/blog/pool-vs-ett/)**
Análisis detallado de costes, tiempos y beneficios de ambos modelos para
que elijas el más adecuado para tu hospital.

**[Casos de Éxito: Hospitales que Redujeron Costes 30% con Pools](/blog/casos-exito-pools/)**
Descubre cómo 5 hospitales privados en Barcelona y Madrid transformaron su
gestión de personal eventual.

**[Guía Legal: Contratación Eventual Sanitaria en España](/blog/marco-legal-eventual/)**
Todo lo que necesitas saber sobre el marco legal, límites de contratos, y
compliance.
```

**3. Navegational Links** (breadcrumbs, menus):
- Facilitan navegación
- También cuentan para SEO

### Anchor Text Best Practices

**✅ Hacer**:
- Usar keywords relevantes
- Ser descriptivo (usuario sabe a dónde va)
- Variar anchor text para mismo target (no siempre exactamente igual)
- Hacer link en frase completa cuando tenga sentido

**❌ Evitar**:
- "Click aquí", "leer más", "este enlace" (no descriptivos)
- Anchor text demasiado largo (>8-10 palabras)
- Exactamente mismo anchor text 10 veces para misma página

**Ejemplos**:

**❌ Mal**:
```markdown
Para saber más sobre pools de enfermeras, haz clic [aquí](/pool/).
```

**✅ Bien**:
```markdown
Descubre cómo funcionan los [pools de enfermeras](/pool/) y por qué están
reemplazando a las ETTs tradicionales.
```

**✅ Variaciones para mismo target** (/pool/):
- "pool de enfermeras"
- "pools digitales de personal sanitario"
- "cómo funciona un pool de enfermeras"
- "plataformas de pool para hospitales"

## Conclusión

La estructura del contenido no es opcional; es fundamental para SEO, UX y conversión.

**Checklist final antes de publicar**:

**Estructura**:
- [ ] Un solo H1 con keyword principal
- [ ] 3-7 H2s con flujo lógico
- [ ] H3s para fragmentar secciones largas
- [ ] Jerarquía correcta (no saltar de H1 a H3)

**Contenido**:
- [ ] Intro con hook, problema y promesa (100-150 palabras)
- [ ] Párrafos cortos (2-4 oraciones)
- [ ] Listas y tablas para escaneo fácil
- [ ] Bold para destacar keywords y datos
- [ ] Conclusión con resumen y CTA claro

**Visual**:
- [ ] Imagen hero con alt text
- [ ] Imágenes in-content cada 300-400 palabras
- [ ] Todas las imágenes optimizadas (<150 KB)
- [ ] Alt text descriptivo en todas

**Links**:
- [ ] 3-5 internal links con anchor text descriptivo
- [ ] Sección "Artículos Relacionados" al final
- [ ] Links externos a fuentes autorizadas (si se citan datos)

**SEO**:
- [ ] SEO title (50-60 chars)
- [ ] Meta description (150-160 chars)
- [ ] Keyword principal en H1, intro, conclusión
- [ ] Keywords secundarias distribuidas naturalmente
- [ ] FAQ section (para artículos >1500 palabras)

**Conversión**:
- [ ] Al menos 2 CTAs (inline + conclusión)
- [ ] CTAs específicos y relevantes al contenido
- [ ] Testimonios o prueba social (para landing pages)

**Calidad**:
- [ ] Sin errores ortográficos o gramaticales
- [ ] Tone of voice consistente con Livo
- [ ] Datos verificados y actualizados
- [ ] Author byline (si aplica para E-E-A-T)
