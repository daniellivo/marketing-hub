## 📋 Checklist Pre-Publicación (How-To Guide)

### Contenido
- [ ] Cada paso tiene objetivo claro y tiempo estimado
- [ ] Instrucciones son específicas y accionables (no vagas)
- [ ] Incluye capturas de pantalla o diagramas en pasos clave
- [ ] Sección de troubleshooting con 3+ problemas comunes
- [ ] Checklist de verificación al final de cada paso crítico
- [ ] Resultado final es medible y verificable

### Formato How-To Específico
- [ ] Pasos numerados en orden secuencial lógico
- [ ] Tiempo total de implementación especificado
- [ ] Requisitos y materiales listados al inicio
- [ ] Vista general del proceso antes de entrar en detalles
- [ ] Sub-pasos dentro de cada paso principal están numerados
- [ ] Código/comandos en bloques de código formateados

### SEO para How-To
- [ ] Título sigue formato "Cómo [Acción] en [Contexto]"
- [ ] URL incluye "como-[keyword-principal]"
- [ ] Keywords "cómo", "paso a paso", "guía" distribuidas
- [ ] Schema markup para HowTo (si CMS lo soporta)
- [ ] Imágenes numeradas (paso-1, paso-2, etc) con alt text descriptivo

### GEO para How-To
- [ ] Cada paso puede ser extraído como snippet independiente
- [ ] Troubleshooting usa formato Problema → Solución
- [ ] Métricas de éxito específicas (no vagas)
- [ ] Checklist final extractable para AI
- [ ] FAQ cubre preguntas "cuánto tiempo", "qué necesito", "qué pasa si"

### User Experience
- [ ] Nivel de dificultad indicado (Principiante/Intermedio/Avanzado)
- [ ] Tiempo estimado realista (testea el proceso)
- [ ] Warnings/cautions antes de acciones irreversibles
- [ ] Pro tips para usuarios avanzados
- [ ] Sección "Próximos pasos" para continuar aprendizaje

### Livo-Específico
- [ ] CTA relevante al proceso (no genérico)
- [ ] Conexión natural con producto Livo que automatiza/facilita el proceso
- [ ] Ejemplos del sector sanitario cuando sea posible
- [ ] Tono profesional pero accesible (no condescendiente)

## 💡 Consejos para Usar Este Template

1. **Testea el proceso**: Sigue tu propia guía paso a paso para verificar que funciona y que los tiempos son realistas.

2. **Un objetivo por guía**: No intentes resolver múltiples problemas. "Cómo X" debe tener un X muy específico.

3. **Capturas específicas**: Las imágenes deben mostrar exactamente qué hacer, no screenshots genéricos.

4. **Anticipa errores**: La sección de troubleshooting es crítica. Incluye errores que TÚ cometiste al probar.

5. **Mantén actualizado**: How-to guides se vuelven obsoletos. Revisa cada 3-6 meses si herramientas/procesos cambiaron.

6. **Verificación es clave**: Al final de cada paso importante, el lector debe poder auto-verificar que lo hizo bien.
