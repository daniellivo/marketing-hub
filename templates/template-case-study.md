## 📋 Checklist Pre-Publicación (Case Study)

### Estructura de Caso
- [ ] Sigue estructura Situación → Problema → Solución → Resultados → Aprendizajes
- [ ] Resultados cuantificables en múltiples lugares (título, resumen, sección dedicada)
- [ ] Timeline claro del proyecto con hitos
- [ ] Testimonios de múltiples stakeholders (mínimo 2)
- [ ] Desafíos y cómo se superaron (no solo éxitos)

### Credibilidad y Datos
- [ ] Métricas específicas (no "mucho mejor" sino "45% mejor")
- [ ] Todos los claims tienen fuente o dato que los respalde
- [ ] Cliente real identificado (o razón válida para anonimato)
- [ ] Fecha de implementación y verificación de datos incluida
- [ ] ROI calculado y presentado honestamente
- [ ] Comparación antes/después con números reales

### Storytelling
- [ ] Comienza con el problema (no con la solución)
- [ ] Incluye contexto emocional/humano (no solo números)
- [ ] Quotes auténticos del cliente (no genéricos)
- [ ] Describe el "por qué" de las decisiones, no solo el "qué"
- [ ] Narrativa tiene arco: desafío → lucha → éxito

### Aplicabilidad
- [ ] Sección dedicada a "lecciones aplicables"
- [ ] Guidance específica por tipo de organización
- [ ] Checklist de "¿estás listo para esto?"
- [ ] Roadmap de "cómo empezar"
- [ ] Factores críticos de éxito claramente identificados

### SEO para Case Studies
- [ ] Título incluye resultado específico y métrica
- [ ] URL incluye "caso" + keyword relevante
- [ ] Alt text en gráficas describe los datos mostrados
- [ ] Schema markup para Organization y Review si aplica
- [ ] Keywords relacionadas con la industria y problema

### GEO para Case Studies
- [ ] Ficha técnica extractable como snippet estructurado
- [ ] Resultados presentados en formato de lista extractable
- [ ] FAQ responde preguntas típicas sobre casos (¿cuánto tiempo?, ¿es típico?, etc.)
- [ ] Secciones de desafíos usan formato Problema → Solución → Resultado
- [ ] Métricas presentadas en formato comparable (Antes: X → Después: Y → Mejora: Z%)

### Visual y Formato
- [ ] Métricas destacadas visualmente (cajas, colores)
- [ ] Gráficas antes/después para métricas clave
- [ ] Fotos del cliente/instalaciones (con permiso)
- [ ] Timeline visual del proyecto
- [ ] Infografía resumen de resultados

### Ética y Transparencia
- [ ] Consentimiento del cliente para publicación documentado
- [ ] Resultados no exagerados ni cherry-picked
- [ ] Desafíos y limitaciones incluidos honestamente
- [ ] Contexto suficiente para entender por qué funcionó
- [ ] Disclosure si cliente está incentivado/pagado por testimonial

### CTA y Conversión
- [ ] CTA relevante y natural (no forzado)
- [ ] Múltiples CTAs para diferentes niveles de interés (demo, más casos, contacto)
- [ ] Link a ROI calculator o assessment tool
- [ ] Pathways claros para lectores en diferentes etapas (awareness, consideration, decision)

## 💡 Consejos para Usar Este Template

1. **Consigue permiso ANTES**: No publiques casos sin consentimiento explícito del cliente, incluso si anonimizan.

2. **Datos reales siempre**: Un caso con datos vagos ("mejoró significativamente") pierde todo el valor. Si no puedes compartir números exactos, usa rangos.

3. **Incluye los desafíos**: Casos que solo muestran éxitos suenan a marketing. Los desafíos reales y cómo se superaron son más valiosos.

4. **Múltiples perspectivas**: Testimonios de diferentes roles (dirección + usuario final) dan más credibilidad que uno solo.

5. **Actualiza regularmente**: Vuelve a contactar al cliente 6-12 meses después para resultados a largo plazo.
